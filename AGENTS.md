# ПРОТОКОЛ РАБОТЫ (обязателен для любой правки; читать перед каждой задачей)

## Главные правила
1. **Одна задача за раз.** Ничего «заодно» не менять.
2. **Сначала воспроизвести** проблему (лог, curl, тест), только потом править код.
3. **Правка минимальная и точечная.** Не переписывать работающее, не добавлять лишнее.
4. **Никогда не деплоить с красными тестами.** Никогда не коммитить без прогона проверок.
5. Если сомневаешься — спросить пользователя, а не догадываться.

## Обязательный цикл правки (все шаги, без пропусков)
1. **Репро**: зафиксировать факт проблемы (журнал/curl/тест).
2. **Правка кода**: минимальная, строго по проблеме.
3. **`./scripts/check.sh`** → должно быть `ALL CHECKS PASSED` (ruff + ≥322 теста (см. ./scripts/check.sh)).
4. **Если менялся webapp** (`webapp/app.js`, `index.html`, `styles.css`, шаблон страницы):
   **`./scripts/gui_check.sh`** → должно быть `GUI-ПРОВЕРКА ПРОЙДЕНА`
   (jsdom: все экраны + очередь/обложка/удаление/папки).
5. **`./scripts/deploy.sh`** → дождаться `>> done`.
6. **Живая проверка**: curl/лог — проблема исчезла И ничего соседнего не сломалось.
7. **Запись в `docs/SESSION_LOG.md`**: что, почему, как проверено.

## Если баг не ловится тестом
Сначала добавить тест, воспроизводящий баг (**regression-first**), затем фиксить.

## Запрещено (после инцидента 2026-09-20)
- Фоновые «самолечащие» скрипты, которые правят маршруты/переподключают сеть
  (route-guard, reconnect-циклы и т.п.) — это устраивало сетевой шторм.
- Вызывать несуществующие функции в JS (проверяется `tests/test_webapp_static.py`).
- Менять схему БД без миграции; удалять файлы пользователя с диска.
- Прятать ошибки (`try/except: pass`) без логирования.

## Диагностика — шпаргалка
- Журнал: `journalctl -u orchestrator --since "-15 min" | grep -vE "httpx|getUpdates"`
- Панель изнутри: `curl "http://127.0.0.1:8080/webapp/api/status?key=$WEBAPP_ACCESS_KEY"`
- Ошибки UI: `./scripts/gui_check.sh` (покажет упавший экран/поток).
- Работа с VM Postiz: `./scripts/runvm.sh '<команда>'`
- Сеть/железо: `bash scripts/network_doctor.sh`

## Ориентиры по коду
- Оркестратор: `src/orchestrator/` (`scheduler.py`, `publisher.py`, `webapp_api.py`,
  `watcher.py`, `status_sync.py`, `postiz_http.py`).
- Панель: `webapp/app.js` (один файл, IIFE; экраны + обработчики `data-act="..."`).
- Тесты: `tests/` (+ `tests/gui/` — GUI-проверка).
- Документы: `docs/HANDOFF.md` (вход), `docs/SESSION_LOG.md` (журнал),
  `docs/INCIDENT-2026-09-20-network.md` (разбор сетевой аварии).
