# Наблюдатель (Watcher) — дизайн-спека

Дата: 2026-10-12 · Статус: на ревью у пользователя

## 1. Задача

Пользователь не хочет ни автопочинки, ни автозапуска ассистента. Нужно, чтобы ошибки системы попадали в Telegram по правилам:

- 🔴 критичное — сразу, одним сообщением;
- 🗒 остальное — одной сводкой раз в день в 13:00 (за последние 24 часа);
- ничего чаще этого; никакого спама; минимальная нагрузка на сеть/роутер.

Плюс ручное управление из Telegram: пауза/возобновление всей системы; по запросу — `/статус` и `/журнал`.

Предыстория: 10–12.10.2026 туннель панели умер и флапал 2 дня (4340 ошибок/сутки), демон крутился в цикле ошибок, старые watchdog'и слали спам. Всё это уже выключено; эта спека — чтобы такое больше не повторилось и чтобы ошибки приходили тихо и по делу.

## 2. Что делает Наблюдатель (на сервере; только чтение; без починки)

Раз в 15 минут (таймер; при сбоях — бэкофф, без per-minute дёрганья) проверяет:

- сервисы: orchestrator / туннель / бот — активны? сколько падений подряд?
- панель: health-endpoint отвечает?
- токены платформ: не истекают ли (предупреждение заранее);
- публикации: ошибки из журнала оркестратора, просроченные, застрявшие;
- инфраструктура: диск, свежесть бэкапа, грубые сбои DNS/сети.

Результат → журнал (локальная БД/файл) с дедупликацией: одна проблема = одна запись + счётчик повторов и время.

Отправка в Telegram:

- 🔴 критичное — сразу: сервер недоступен (внешняя проверка), публикация полностью невозможна, требуется действие пользователя (токен/оплата/место);
- 🗒 сводка 13:00: все ошибки за 24 ч (что, когда, сколько раз повторялось); если пусто — «✅ без ошибок» (чтобы было видно, что система жива).

Наблюдатель НИЧЕГО не перезапускает и не исправляет. Увидел → записал → сообщил.

## 3. Пауза / Возобновление

- Команда/кнопка в Telegram → флаг паузы: публикации останавливаются, Наблюдатель молчит (не проверяет и не пишет), бот остаётся только слушать «Возобновить».
- Та же кнопка в панели 8.6.0 (там уже есть пауза по платформам — добавим общую).
- При постановке на паузу — одно подтверждение. Во время паузы сводка 13:00 не отправляется (полная тишина).

## 4. По запросу (pull — не спамит)

- `/статус` — краткая картина сейчас (что работает, сколько публикаций, пауза?).
- `/журнал` — последние N записей журнала.

## 5. Внешняя проверка (с Мака; без ИИ)

- launchd-скрипт раз в 15 мин: сервер отвечает (по Tailscale/LAN)? Две неудачи подряд → сообщение в Telegram «сервер недоступен».
- Зачем: Наблюдатель живёт на сервере — о полном падении сервера он сообщить не сможет.
- Мак спит → проверка подождёт пробуждения (это ок).

## 6. Сеть/роутер

- Проверки раз в 15 мин — копейки трафика.
- Постоянный туннель (named, на домене) вместо trycloudflare; systemd-бэкофф вместо штормов.
- Никаких per-minute таймеров и массовых ретраев.

## 7. Этапы внедрения

1. Наблюдатель + журнал + сводка — вместе с запуском 8.6.0 (пока система выключена — наблюдать нечего).
2. Telegram-команды (пауза/возобновление, `/статус`, `/журнал`) — вместе с ботом 8.6.0.
3. Внешняя проверка с Мака — отдельным шагом.

## 8. Явно НЕ делаем

- Автопочинку и перезапуски.
- Автозапуск ассистента (пользователь зовёт сам, в чат).
- Любые сообщения чаще: критичное сразу + сводка 1/день.
- Per-minute таймеры; trycloudflare-туннели; спам-алерты.
