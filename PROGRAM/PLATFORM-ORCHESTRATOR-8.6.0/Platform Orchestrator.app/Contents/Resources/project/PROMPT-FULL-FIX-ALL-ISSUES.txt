# 1. СТАНДАРТЫ НАПИСАНИЯ КОДА (обязательны)
################################################################################

1.1 Стиль
  - Python 3.11+ typing где уместно; без противоречий существующему стилю пакета
    orchestrator (уже принятые dataclass/BaseModel/logging).
  - Имена: snake_case функции/модули, PascalCase классы.
  - Без мёртвого кода, без закомментированных «на всякий случай» блоков >5 строк.
  - Без print() в library-коде src/ — только logging.
  - Docstrings на публичных функциях, которые менялись по смыслу.

1.2 Архитектура hard-cut
  - Не возвращать PostizClient / HttpPostiz / MockPostiz / live Postiz API в src/.
  - Не dual-write в legacy_post_id / legacy_scheduled_for (только NULL cleanup
    и миграция RENAME в db.py).
  - Новые EPS: external_id, external_sub_id, external_url, scheduled_for, source.
  - engines: только module:* | n8n | browser | direct.
  - В src/ слово "postiz" — ТОЛЬКО пара строк миграции в db.py (RENAME COLUMN).

1.3 Качество правок
  - Правки минимально необходимые, но полные по требованиям этого документа.
  - Не ломать публичные сигнатуры без обновления всех call-site в src/ и tests/.
  - После rename/рефактора — rg по старому символу, пока hits не осмысленны.

1.4 Форматирование
  - Если в репо есть ruff/black/isort — прогнать на изменённых файлах.
  - Не оставлять SyntaxError / undefined name (platformEngine и т.п.).
