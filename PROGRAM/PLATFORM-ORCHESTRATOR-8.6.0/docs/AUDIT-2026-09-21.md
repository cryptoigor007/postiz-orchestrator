### P0-1. Неаутентифицированное чтение произвольных файлов через статику панели
`src/orchestrator/webapp_api.py:1807` (`_file`), ветка статики `:296-334`.

`Path(WEBAPP_DIR) / name`, где `name` — из URL. Ведущий `/` давал абсолютный путь
(`Path("/opt/orchestrator/webapp") / "/etc/host.conf"` == `/etc/host.conf`); проверялся только

`/opt/orchestrator/data/data.sqlite` (544 КБ), `/etc/orchestrator/postiz-ca.pem`.

**Фикс:** containment в `_file` (resolve + путь обязан быть внутри `WEBAPP_DIR`, ведущие `/`
срезаются). Регресс-тест `test_build_path_rejects_absolute_and_dotdot`. Проверено на проде:

## P1 — высокий приоритет

### P1-1. `publishing` — вечный дедлок: сущность больше не публикуется никогда
`src/orchestrator/publisher.py:56-101` + early-return `:143-145,153-156,160-164,166-172,189-192`.

`_reserve_publish()` атомарно ставит `status='publishing'` и коммитит. Все последующие ранние
выходы (платформа disabled, safety-block, конфликт `ScheduleGuard`, read-only, hourly-limit) **не
откатывают** резерв. `_already_exists()` (`:52-53`) после этого вечно возвращает `"__publishing__"`.
Сброса `publishing` нет нигде; `queue/restore` чинит только `skipped`.

**Репро:** `pause_platform('youtube')` → `publish()` → строка `publishing/pid=NULL`; после
`resume_platform` `publish()` снова ничего не делает. Лечится только удалением строки.
**Фикс:** снимать резерв на всех return после `_reserve_publish`; watchdog по TTL для `publishing`.

### P1-2. Флаг `--read-only` не работает — публикует «вживую»
`src/orchestrator/main.py:154-155`. `args.read_only` больше нигде не читается, `cfg.read_only`
не существует, `ORCH_READ_ONLY` не выставляется. Защита (`publisher.py:166`, `webapp_api.py:346`)
смотрит только env. `orchestrator --read-only --schedule` создаёт реальные посты.
**Фикс:** при `args.read_only` выставлять `os.environ["ORCH_READ_ONLY"]="1"`.

### P1-3. Бэклог не раскладывается при override-расписаниях → платформа встаёт навсегда
`scheduler.py:564-601` (`_backlog_slots` берёт сырой `self.cfg.schedules`) против
`scheduler.py:57-66` (`_is_canonical` валидирует по `sched_settings.effective`). Любой
платформенный/групповой override → все слоты бэклога `non_canonical_slot`, раскладка = 0,
`series_tail_mode` не снимается, новая серия блокируется (`scheduler.py:93-110`).
**Репро:** override youtube long=11:15/thematic=19:00/standalone=10:00 → `resolve('distribute')=0`,
`has_backlog=2`, `schedule_long_videos()=0`. **Фикс:** строить `_backlog_slots` через `effective(...)`.

### P1-4. Счётчик «пропал в Postiz» не сбрасывается; `error` — терминальное состояние
`status_sync.py:29-34,61-92`. При успешном `get_post` `last_error` не очищается → порог «3

**Фикс:** сбрасывать `last_error` при успехе; включить `error`+pid в выборку.

### P1-5. Ответ «Ждать»/«Не публиковать» не сохраняется — спам вопросом и принудительная раскладка
