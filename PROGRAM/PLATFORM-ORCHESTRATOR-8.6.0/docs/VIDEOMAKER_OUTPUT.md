# Стандарт вывода видео мейкера (v1.0)

Документ фиксирует, как устроена «стандартная папка вывода работы видео мейкера» и по каким
правилам оркестратор выбирает из неё файлы для публикации. Реализовано в 8.4.18 / b835.

## 1. Структура

```
<корень>/<номер серии>/                     ← единица учёта, имя папки = номер серии
├── info_metadata.txt                       ← производство серии (общее для всех платформ)
│                                              series, audio,
│                                              package_title, package_hook, package_hashtags
│                                              + блок Shorts: title/description/hashtags/start/end
├── <картинка-1>, <картинка-2>              ← обложки серии: имена ЛЮБЫЕ, определяем по пропорциям
└── <платформа>/                             ← самодостаточный пакет: youtube, telegram, instagram, tiktok, facebook
    ├── vertical/                            ← 9:16
    │   ├── final_9x16.mp4
    │   └── <номер>_title.txt / _hook.txt / _description.txt / _hashtags.txt
    ├── wide/                                ← 16:9
    │   ├── final_16x9.mp4
    │   └── <номер>_*.txt
    └── shorts/
        └── short_NNN/
            ├── short_NNN.mp4                (или *_final.mp4)
            ├── short_NNN_cover.jpg
            └── short_NNN_{title,description,hashtags,hook}.txt
```

Первый реальный пример: `/mnt/video/broll_downloads/7` (на Mac — `/Volumes/video/broll_downloads/7`),
4,6 ГБ, серия 7 «Тайный кризис», пакет `youtube/` + 5 шортсов.

## 2. Правила выбора файлов

1. **Серия** — папка с `info_metadata.txt` и хотя бы одним пакетом платформы.
   `title` в базе = имя папки, `title_text` = `package_title`.
2. **Платформа** — подпапка с именем платформы из конфига (`youtube`, `telegram`, …).
3. **Длинное видео** — только `<платформа>/<формат>/final_*.mp4`, где формат определён таблицей
   из §4. `master_*` не берём никогда. Нет файла нужного формата — у платформы по этой серии
   публикации нет, подстановка файлом другого формата запрещена.
4. **Шортсы** — из пакета самой платформы: `<платформа>/shorts/short_NNN/short_NNN.mp4`.
   Порядок — по имени папки. Кросс-платформенного переиспользования нет.
5. **Тексты** — сначала из пакета платформы (`<номер>_*.txt` в `vertical/`, иначе `wide/`),
   если там пусто — с уровня серии (`package_*` из `info_metadata.txt`).
   Тексты шортса — `short_NNN_*.txt`; `short_NNN_meta.txt` — только для человека.
6. **Только `final_*`**: без финала у платформы нет публикации, и это видно в панели
   («Пакеты платформ без final (не публикуются)»), а не растворяется в тишине.
7. **Старый формат** без пакетов (`<серия>/{vertical,wide,shorts}`) продолжает работать —
   все прошлые серии и текущая база сделаны так.

## 3. Обложки: определяем по формату, не по имени

Имена файлов могут быть любыми (`cover.jpg`, `7_cover_16x9.jpg`, `photo-1.png`,
или просто две картинки). Алгоритм:

1. Смотрим картинки в корне серии (`*.jpg`, `*.jpeg`, `*.png`, `*.webp`), пропуская `._*`
   и `.DS_Store`; картинки внутри `vertical/`, `wide/`, `shorts/` обложками серии не считаются
   (там обложки шортсов).
2. Читаем размеры и классифицируем по пропорции: высота > ширины — **вертикальная (9:16)**,
   ширина > высоты — **горизонтальная (16:9)**, примерно квадрат — **универсальная**.
3. Если картинок несколько — берём самую крупную вертикальную и самую крупную горизонтальную.
4. Использование: платформа, публикующая wide, получает горизонтальную; платформа,
   публикующая vertical (и шортсы), — вертикальную. Если есть только одна картинка —
   её получает только «свой» формат, второй формат публикуется без обложки. Квадратная идёт обоим.
5. Обложка шортса — `short_NNN_cover.jpg` из папки шортса.

**Сейчас в базе одно поле `cover_path`**, и обложку грузит только YouTube (`publisher.py`,
`platform == "youtube"` → thumbnail). Поэтому в `cover_path` попадает **горизонтальная** обложка:
вертикальную не отдаём горизонтальной площадке. Вертикальные площадки (tiktok/instagram/facebook)
пока выключены; когда включим их с обложками — понадобится миграция под две картинки
(`cover_wide_path`, `cover_vertical_path`).

## 4. Платформы и форматы

| Платформа | Длинное видео | Шортсы |
|---|---|---|
| youtube | **только wide (16:9)**; папка `youtube/vertical/` игнорируется, даже если файлы есть — **в базу не пишем, никому не отдаём** | из `youtube/shorts/` |
| telegram | ссылка на YouTube, файл не грузим (`post_mode: link`) | из `telegram/shorts/` |
| instagram | vertical (9:16) | из `instagram/shorts/` |
| tiktok | vertical (9:16) | из `tiktok/shorts/` |
| facebook | **пока не решено** (по умолчанию wide) | из `facebook/shorts/` |

Шортсы должны быть у каждой платформы свои.

## 5. Что всегда игнорируем

`._*` (AppleDouble от macOS), `.DS_Store`, `master_*`, `temp/`, `used/`, `ссд/`,
`Vertical/`, `Wide/`, `*.app`, `shorts_overflow`, `_tmp`, `broll_downloads` (пока корень не решён).

## 6. Реализация в коде

- `watcher.py`:
  - `_package_dirs()` — пакеты платформ внутри папки серии; `_variant()` — формат платформы
    из `platforms.<name>.video_variant` (`wide`/`vertical`);
  - `_platform_map()` — карта платформа→файл: у пакета берётся только свой формат и только
    `final` (`_final_mp4()`), вертикаль внутри `youtube/` не берётся;
  - `_scan_long()` — `folder_path` на уровне папки серии, `wide_path`/`vertical_path` только из
    пакетов «своего» формата, `platform_paths` (JSON) — строгая карта платформы;
    счётчик `no_final` для панели;
  - `_scan_shorts_dir()` + `_shorts_dirs()` — шортсы пакета принадлежат только своей платформе
    (`platform_paths={"<платформа>": …}`), плюс старый общий `shorts/`;
  - `_series_covers()` — обложки по размерам (`_image_size()`: PNG/JPEG/WebP без внешних библиотек);
  - `_is_episode()` — серия распознаётся и по пакетам платформ, не только по `vertical/`+`wide/`;
  - `._*` исключены в текстах, метаданных и обложках; привязка шортсов к фильму работает
    для вложенных пакетов (`<серия>/<платформа>/shorts/...`).
- `scheduler.py`: `_pick_path()` и `_pick_short_path()` — если `platform_paths` заполнена,
  она строгая: платформа без своего файла публикации не получает.
- `webapp_api.py` + `webapp/app.js`: скан отдаёт `no_final`, панель показывает
  «Пакеты платформ без final (не публикуются)».
- Тесты: `tests/test_watcher.py` (пакет платформы, обложки по размерам, пропуск без final,
  старый формат), `tests/test_scheduler.py` (строгий выбор файла платформы).

## 7. Открытые вопросы

- **Корень вывода** (решает владелец): остаётся `broll_downloads/<N>/…` или отдельная папка.
  Сейчас корень скана — сама папка серии; `broll_downloads` в «мусорном» списке.
- **Facebook**: wide или vertical.
- В корне серии `7` обложек пока нет — как только появятся, подхватятся автоматически
  (горизонтальная уйдёт в YouTube, вертикальная сохранится для вертикальных площадок).
