1. ЧТО ДОЛЖНО РАБОТАТЬ ДО ПОДАЧИ (продуктовая готовность)
--------------------------------------------------------------------------------
1.1 Пользовательский путь (обязателен для демо):
    (а) Подключение TikTok через Login Kit (OAuth, кнопка «Connect TikTok»);
    (б) Экран компоуза: выбор видеофайла, заголовок/описание/хэштеги;
    (в) ПРИВАТНОСТЬ выбирается вручную (без дефолта!), переключатели
        комментариев / duet / stitch — тоже руками;
    (г) Экран подтверждения: «Я подтверждаю публикацию» (явное согласие);
    (д) Планирование даты/времени ИЛИ публикация сейчас;
    (е) Статус публикации (обработка → опубликовано) и ссылка на пост.
1.2 Ограничения, которые демонстрируем осознанно: уважение лимитов платформы,
    обработка ошибок с человекочитаемыми сообщениями, отключение аккаунта одной
    кнопкой, удаление данных по запросу.
1.3 Отдельный тестовый TikTok-аккаунт (не боевой) — на нём снимаем демо
    и на нём же проверяем ревью-контур.

3. ГОТОВЫЕ ТЕКСТЫ
--------------------------------------------------------------------------------
=== 3.1 APP DESCRIPTION (EN — для портала) ===
Name: Tochka Scheduler
Category: Productivity
Description (short):
  A scheduling app for a creator's own TikTok account: compose a post
  (caption, hashtags), choose privacy and interaction settings manually,
  confirm, and schedule it for a selected time. Publishes original videos
  only; no bulk uploads, no third-party accounts.
Description (long):
  Tochka Scheduler is a personal content tool for a creator who publishes
  their own original short videos. The user connects their own TikTok
  account, selects a video, writes the caption and hashtags, explicitly
  chooses the privacy level (no default is applied) and interaction
  settings (comments, duet, stitch), confirms the post, and either
  publishes it immediately or schedules it for a chosen date and time.
  The app shows the publication status and respects TikTok's rate limits.
  The app does not accept content for accounts the user does not own and
  does not perform any posting without the user's explicit confirmation.

=== 3.2 PRIVACY POLICY (EN) — публикуется на /privacy ===
Effective date: <дата>
Tochka Scheduler ("the App", "we") helps the account owner publish their own
videos to their own TikTok account.
1. Data we process
   - TikTok account data returned by Login Kit: open_id, username, display name,
     avatar. Access and refresh tokens issued by TikTok.
   - Content the user submits: video files, captions, hashtags, scheduling data.
   - Technical logs: request statuses and errors (without tokens).
2. Why
   - To authenticate the user, publish and schedule the user's own content,
     show publication status, and diagnose errors.
3. How we store
   - Tokens are stored on our server and protected from public access.
   - Video files are stored temporarily and deleted after publication or on request.
   - We do not sell or share personal data with third parties.
4. Retention and deletion
   - Tokens are stored until the user disconnects the account.
   - The user may disconnect at any time (revoking access) and request full data
     deletion by email: <email>.
5. Security
   - Access to the server is restricted; secrets are not exposed.
6. Children
   - The App is not intended for users under 13.
7. Changes and contact
   - We will update this page when the policy changes. Contact: <email>.

=== 3.4 USE CASE / REVIEW NOTES (EN — в форму review) ===
- Who uses it: one creator (the account owner) for their own account.
- What it does: manual compose → manual privacy selection → explicit
  confirmation → schedule/publish ORIGINAL videos.
- Why Direct Post API is needed: to publish at the user's selected future time
  with the user-selected privacy, without manual last-minute steps.
- What it explicitly does NOT do: no bulk uploads, no publishing to accounts
  the user does not own, no automated posting without explicit user action,
  no automation of engagement (likes/comments/duets).
- How reviewers can test: test account credentials + step-by-step instructions
  are attached in the review form (§6.5).

4. ДЕМО-ВИДЕО (покадровый сценарий; длительность 2:30–3:30)

7. ЧАСТЫЕ ПРИЧИНЫ ОТКАЗА И ЧТО ДЕЛАТЬ
--------------------------------------------------------------------------------
1) Недоступна политика/условия → поднять на GitHub Pages, проверить curl -I.
2) Демо не показывает direct post или приватность ставится по умолчанию → переписать UX
   (приватность только руками) и переснять демо.
3) «Похоже на утилиту для управляемых аккаунтов» → переписать позиционирование
   (продукт для автора, свой аккаунт, свой оригинальный контент), добавить явные
   ограничения в описание.
4) Redirect URI mismatch → исправить и переотправить.
5) Нет инструкций для тестировщика → добавить пошагово (со скриншотами).
6) Отказ без причины → запросить разъяснение в тикете/апелляции, приложить
   соответствие чек-листу §6.
После отказа: исправить перечисленное → повторная подача. Количество попыток
не ограничено; после обмана — считай, что закрыто навсегда.
