# Бэкап сервера (без медиафайлов) и копия на Mac

Запуск с Mac из корня репозитория:

```bash
bash scripts/backup_server.sh
```

Скрипт собирает архив **на сервере**, кладёт его в `/root/backups/` (ротация: последние 7)
и скачивает копию в `~/backups/` вместе с контрольной суммой. Сумма проверяется сразу после
скачивания — если не совпала, скрипт падает и ничего не подтверждает.

Переменные: `PVE_HOST` (по умолчанию `root@100.95.225.71`), `BACKUP_DIR` (`~/backups`), `KEEP` (7).

## Что внутри архива
| Папка | Что сохраняется |
|---|---|
| `orchestrator/` | `config.yaml`, `.env` (секреты), `data/data.sqlite`, `data/metrics.json`, сертификаты |
| `systemd/` | юниты `orchestrator`, `cloudflared-webapp`, `cloudflared-url-sync` (+ список запущенных сервисов) |
| `proxmox/` | `/etc/pve` (конфиги всех VM и CT), **весь `/etc` хоста**, список 1028 пакетов, версии Proxmox, layout дисков (`lvs/vgs/pvs`), конфиг каждой VM, сеть, `hosts`, `fstab`, списки `qm`/`pct` |
| `postiz/` | `docker-compose.yml`, **каталог `/home/postiz` с `patch/Dockerfile`** (из него собирается образ `postiz-fixed`, которого нет в интернете), списки контейнеров/образов/томов, **дамп базы Postgres** (`pg_dump`, gzip) |
| `RESTORE.md` | пошаговая инструкция восстановления (лежит внутри архива) |

## Восстановление скриптами (за 4 команды)
Внутри архива лежит `restore/` — набор скриптов, которые делают работу за человека:
```bash
tar -xzf orch-server-*.tar.gz && cd orch-server-*
bash restore/host.sh .        # хост: /etc, конфиги VM, ключи, /usr/local, cloudflared, сервисы
bash restore/vm-create.sh .   # если VM Postiz потеряна (образ Ubuntu скачается сам)
bash restore/vm-data.sh .     # docker, каталог Postiz, compose, ВСЕ базы, пересборка образа
bash restore/app.sh .         # оркестратор: код, настройки, секреты, база, окружение, сервис
bash restore/checks.sh .      # проверка: панель, API, кнопка в Telegram, VM, база
```
Скрипты идемпотентны (можно запускать повторно), `checks.sh` в конце печатает
«ИТОГ: восстановление подтверждено — всё работает» либо список проблем.

**Проверено вживую 23.09:** `app.sh` развернул оркестратор из архива в отдельный каталог за
**8 секунд** (код, настройки, секреты, база, окружение), панель ответила; прогон тестов
восстановленным кодом дал тот же результат, что на проде (425 прошло, 2 падают одинаково из-за
окружения — не из-за бэкапа); `checks.sh` прошёл все пункты. Полный цикл восстановления
(хост → VM → базы → оркестратор) оценивается в 10–15 минут, из них основное время — скачивание
docker-образов и сборка образа Postiz.

Ещё в архиве: `proxmox/cloudflared-linux-amd64` (бинарник, чтобы не зависеть от интернета при
восстановлении; отключается `BACKUP_WITH_BINARY=0`) и `proxmox/_video_disks.txt` — состав и объёмы
видео-дисков `/mnt/video`, `/mnt/ssd_src` (сами медиа не копируются, но видно, что там было).

## Личные файлы владельца (раздел `personal/`)
По флагу `BACKUP_PERSONAL=1` в архив кладётся всё, что не нужно для подъёма машины, но принадлежит
владельцу (388 КБ, архив становится ~5 МБ):
- `personal/broll_downloader.tgz` — его инструмент: код, `broll.db` (1,5 МБ), `status.txt` (venv 26 МБ не входит);
- `personal/root-files.tgz` — свои скрипты (`fix-wifi-lan.sh`, `install-zenbook-lid-display.sh`,
  `check-lid-edp.sh`), дампы железа (`dsdt.dat`, `ss*.dsl` и прочие `.dat`), сетевые бэкапы от 11.08,
  `.bash_history`, старые копии `config.yaml`;
- `personal/vm-root-misc.tgz` — служебные мелочи с VM Postiz (`.pm2`, `.bashrc`, `.profile`).

Осознанно **не** входят: `legacy-logs` (51 МБ), старые архивы отката оркестратора (37 МБ),
копии серверных бэкапов (327 МБ — уже лежат на Mac), кеши (`.cache` 21 МБ, `venv` 26 МБ).

## Проверка, что из архива реально восстанавливается
```bash
bash scripts/backup_restore_test.sh    # самый свежий архив
```
Скрипт распаковывает архив и **проверяет восстановление, а не наличие файлов**:
- `config.yaml` разбирается тем же загрузчиком, что и в проде (проекты, платформы, проект по умолчанию);
- база очереди открывается: таблицы и число строк (видео, шортсы, статусы платформ), наличие ключей в `.env`;
- дамп Postiz разворачивается в **чистый временный Postgres** на VM (прод не затрагивается),
  проверяются базы `postiz`/`temporal`/`temporal_visibility` и число таблиц; контейнер удаляется.

Проверено 23.09: конфиг — 2 проекта и 5 платформ, база — 9 таблиц и 4961 строка,
дамп Postiz — 69 таблиц после разворота с нуля.

## Проверка архива по чек-листу
```bash
bash scripts/backup_verify.sh                 # проверит самый свежий архив из ~/backups
bash scripts/backup_verify.sh путь/к/архиву   # или конкретный
```
Скрипт распаковывает архив и проверяет 44 пункта: конфиги хоста и VM, ключи ssh, версии пакетов,
свои скрипты из `/usr/local` (в том числе `cloudflared_url_sync.sh`), юниты и таймеры, код и базу
оркестратора, compose, патч образа, `/etc` и ключи гостя, дампы всех баз, наличие инструкции.
Итог: `ИТОГ: чек-лист пройден полностью` — значит по архиву машина поднимается с нуля.

Важная тонкость при правке проверок: нельзя писать `команда | grep -q` — при `set -o pipefail`
grep выходит на первом совпадении, источник получает SIGPIPE, и проверка ложно падает.
Скрипт считает совпадения (`grep -c`) без раннего выхода.

## Чего в архиве нет (осознанно)
- Видео, обложки, `uploads` и любые медиафайлы — они пересоздаются публикациями.
- Образы и диски виртуальных машин (десятки гигабайт) — восстанавливаются из Proxmox-бэкапов ВМ.
- Логи, `venv`, кеши.
- Код оркестратора: он живёт в репозитории (и на сервере перезаписывается деплоем).

Итоговый размер — около 1 МБ (проверено 23.09: 979 КБ). Так мало, потому что внутри настройки
и дампы, а не данные: конфиг VM — текстовый файл, база Postiz в дампе — 200 КБ, `/etc` хоста — 663 КБ.

Осознанно **не** входят (и почему это не потеря):
- диск VM Postiz (**237 ГБ**, `local-lvm:vm-120-disk-0`) — из него восстановимы только настройки,
  а медиа и так не копим;
- медиа в docker-томах (`postiz_postiz_uploads` и др., **69 ГБ**);
- образ `postiz-fixed:v1.47.2` (**5.66 ГБ**, в интернете его нет) — но он **пересобирается**
  из `postiz/patch/Dockerfile`, который лежит в архиве;
- сам Proxmox как ОС — переустанавливается, а список пакетов и весь `/etc` в архиве есть.

Если понадобится «всё как есть» — отдельно можно снять образ (`docker save`, ~2–3 ГБ в сжатом виде)
или полный бэкап VM через `vzdump` (это уже сотни гигабайт).

## Восстановление
1. Оркестратор: `orchestrator/config.yaml` и `orchestrator/.env` → в `/opt/orchestrator/`,
   `data/` → в `/opt/orchestrator/data/`, сертификаты → в `certs/`; затем `systemctl restart orchestrator`.
2. systemd: юниты → в `/etc/systemd/system/`, затем `systemctl daemon-reload && systemctl enable --now orchestrator cloudflared-webapp`.
3. Proxmox: `proxmox/pve-etc.tar.gz` распаковать в `/etc/` (конфиги VM/CT — `qemu-server/*.conf`, `lxc/*.conf`).
4. Postiz: `postiz/docker-compose.yml` → в `/home/postiz/postiz/` на VM 120, `docker compose up -d`,
   база: `gunzip -c postiz-db.sql.gz | docker exec -i postiz-db psql -U postiz postiz`.

## Важно про секреты
В архиве лежат `.env` (токен бота, ключи Postiz), дамп базы Postiz и ключи из `/etc/pve`.
Хранить копию на Mac нужно как секрет: не выкладывать в облака, не пересылать в мессенджеры.

## Что не помешало бы доделать
- Медиа в бэкапе отсутствует по решению владельца: после восстановления старые видео и обложки
  не вернутся (публикации продолжат работать, потому что подключения и настройки — в базе).
- Если понадобится «диск целиком без медиа» — это отдельный сценарий (около 16 ГБ сырых,
  5–6 ГБ в сжатом виде), по расписанию раз в месяц.

## Автоматизация (по желанию владельца)
Можно повесить еженедельный запуск: `systemd`-таймер на сервере (архив в `/root/backups/`,
ротация 7) + отдельно скачивание на Mac, когда он включён. Обсудить с владельцем.
