# План: несколько проектов (ниш) в одной системе

Запрос владельца (23.09.2026): «Точка наблюдения» — основной проект, но будут параллельные
каналы с другой тематикой (например «Анекдоты», возможно третий — «для души»), публиковать
их надо от имени **своих** аккаунтов в тех же соцсетях. Смешивать контент нельзя.

## Что такое проект

**Проект = ниша.** У проекта свой набор каналов во всех сетях, свой контент, своё расписание
и свои лимиты. Внутри проекта: YouTube-канал, Telegram-канал, страница Facebook, Instagram,
Threads, X — по одному аккаунту на сеть.

```
Проект «tochka»    → youtube:tochka, telegram:tochka, instagram:tochka, facebook:tochka, x:tochka
Проект «anekdoty»  → youtube:anekdoty, telegram:anekdoty, instagram:anekdoty, ...
```

## Ключевые решения (минимум изменений, без переделки схемы БД)

1. **Проект у платформы, а не у строки БД.** В `PlatformCfg` добавляется поле `project`
   (по умолчанию `""` = единственный проект, старое поведение не меняется).
   Ключи платформ остаются глобальными, но каждый описывает свой проект:
   `telegram_tochka`, `telegram_anekdoty`, `youtube_tochka`, `youtube_anekdoty`, …
   Панель показывает их сгруппированно по проекту.
2. **Принадлежность контента проекту выводится из конфига, а не хранится в БД:**
   `projects.<p>.series_ids: [12, 13]` (серии `videomaker`) и `projects.<p>.folders: ["/mnt/video/.../анекдоты"]`
   (обычные шортсы). Схема БД не меняется → миграции не нужны.
3. **Фильтр в планировщике:** перед публикацией сущности проверяем, что проект сущности
   совпадает с проектом платформы (`_project_of(series_id|folder)` + `pcfg.project`).
   Сущности без проекта (не попали в конфиг) публикуются только в платформы без проекта —
   то есть ведут себя как раньше.
4. **Расписание и лимиты** остаются per-platform (`sched_settings`, `limits`), то есть
   у каждого проекта свои дни/время/лимиты автоматически.
5. **Панель:** переключатель проекта (по умолчанию «все»/основной), фильтр по `?project=`.
   Календарь, очередь, ошибки, остаток, статистика — в пределах выбранного проекта.
6. **Уведомления и вопросы бота** адресуются чатам проекта: `projects.<p>.telegram_chat_ids`
   (fallback — глобальный `telegram.allowed_chat_ids`, как сейчас).

## Что нужно от владельца (по этапам)

- Этап 5: аккаунты проекта (Google-канал = бренд-аккаунт, Facebook-страница, Instagram, Threads, X);
  папка на сервере, куда складывать файлы проекта; желаемые дни и время публикаций.

## Открытые вопросы

- Instagram/Threads требуют публичный адрес для медиа (Postiz отдаёт Meta ссылку на файл):
  нужен либо публичный адрес Postiz (Cloudflare), либо облачное хранилище (R2/B2).
  Facebook, YouTube, Telegram, X принимают файл напрямую.
- Один Google-аккаунт = много YouTube-каналов (бренд-аккаунты) → для проектов этого достаточно.
- Facebook/Instagram/Threads заводятся под одним аккаунтом Meta, X — отдельно.
