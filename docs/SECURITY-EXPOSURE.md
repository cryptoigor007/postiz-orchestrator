# Безопасность: что торчит наружу и как развязать сайт от сервера

Владелец 23.09 спросил: «если взломают сервер/сайт — получат доступ ко всему». Ответ и план.

## Почему риск реальный
Оркестратор держит ключи (бот-токен, Postiz, WEBAPP_ACCESS_KEY) в `/opt/orchestrator/.env`,
рядом живут Postiz (VM 120) и данные. Если сайт поднять на этом же хосте, компромисс сайта
даёт доступ к ключам и панели. Поэтому сайт на этом сервере не размещаем.

## Решение (порты не открываем вообще)
1. **Сайт — статический на внешнем бесплатном хостинге** (Cloudflare Pages / GitHub Pages):
   нет сервера, нет БД, нет ключей. Наш сервер не участвует.
2. **Медиа для IG/Threads — во внешнем облаке** (B2/Supabase/R2) с ограниченным ключом
   (только запись/удаление в одном бакете). Утечка ключа не даёт доступа к серверу.
3. **Раздача с нашего сервера (если понадобится)** — отдельный контейнер с nginx, которому
   смонтирована **только папка с готовыми роликами**, без БД, ключей и доступа к системе.
   Худший случай — потеря самих видео.

## Что сейчас слушает (проверено 23.09)
| Порт | Что | Оценка |
|---|---|---|
| 0.0.0.0:8080 | панель оркестратора | слушает все интерфейсы — привязать к 127.0.0.1 |
| 0.0.0.0:22 | sshd, `PermitRootLogin yes` | оставить вход только по ключу (`prohibit-password`) |
| 0.0.0.0:139/445 | Samba | закрыть от интернета или выключить (владелец решает) |
| *:8006 | веб-интерфейс Proxmox | закрыть от интернета, доступ через Tailscale |
| 0.0.0.0:111 | rpcbind | нужен только для Samba/NFS |
| 127.0.0.1:20241 | cloudflared (туннель панели) | ок — только локально |
| 100.95.225.71:42497 | tailscaled | ок — приватная сеть |
| 127.0.0.1:85, :25 | pvedaemon, postfix | ок — только локально |

Снаружи порты закрыты роутером (проверено: `curl` на 89.149.103.173:80/443/8080 → нет ответа),
поэтому прямо сейчас это не дыра. Как только откроем проброс порта — перечисленное станет
видно, поэтому сначала уборка, потом проброс.

## Порядок действий, если владелец захочет раздавать медиа с сервера
1. Уборка: панель на 127.0.0.1, SSH только по ключу, закрыть Samba/pveproxy/rpcbind отвне.
2. DuckDNS-имя + cron обновления адреса; Let's Encrypt для `*.duckdns.org`.
3. Отдельный контейнер с nginx (только чтение папки медиа) + проброс одного порта в роутере.
4. Проверка снаружи: `curl -I https://<имя>.duckdns.org/<file>.mp4` → 200, `content-type: video/mp4`.
