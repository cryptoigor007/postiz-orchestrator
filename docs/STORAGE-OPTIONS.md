# Где хранить медиа для Instagram и Threads (и что ещё умеет каждая сеть)

Решение нужно ровно для двух сетей: **Instagram и Threads**. Их API не принимает файл —
Meta сама скачивает ролик по публичной ссылке. Остальные сети файл принимают напрямую.

| Сеть | Как публикуем | Нужна публичная ссылка |
|---|---|---|
| YouTube | Postiz грузит файл | нет |
| Facebook | Postiz грузит файл (`file_url`/`source`) | нет |
| Telegram | наш бот, файл из Postiz | нет |
| X | через API X (лимиты бесплатного тарифа — проверить) | нет |
| Instagram | `video_url`/`image_url` | **да** |
| Threads | `video_url`/`image_url` | **да** |

Ключевой факт, который снимает вопрос лимитов: **ссылка нужна только на время публикации**.
Meta скачивает файл один раз, дальше он не нужен. Поэтому можно загружать ролик перед
публикацией и удалять после — тогда хватает даже 1 ГБ хранилища.

## Варианты (все бесплатные)

### 1. Свой сервер: DuckDNS + nginx (0 ₽, без лимитов)
- У сервера внешний адрес динамический (провайдер менять не надо). DuckDNS бесплатно даёт
  постоянное имя и обновляется скриптом каждые 5 минут (cron на pve).
- Раздача файлов — nginx с диска: процессор и память почти не тратятся, ограничение —
  скорость отдачи домашнего интернета (150 МБ при 100 Мбит/с ≈ 12 с, при 20 Мбит/с ≈ 1 мин).
- HTTPS — бесплатный сертификат Let's Encrypt (в том числе для `*.duckdns.org`).
- Нужен проброс порта в роутере (`192.168.100.1`). Сейчас снаружи порты 80/443/8080 закрыты.
- Минус: пропал домашний интернет или свет — публикация в IG/Threads сорвётся.

### 2. Backblaze B2 (0 ₽, карта по моим данным не нужна) — рекомендуемый
- 10 ГБ хранения, отдача бесплатно до 3× объёма хранения в сутки (≈30 ГБ/сутки).
- Прямые ссылки вида `https://f000.backblazeb2.com/file/<bucket>/<file>`.
- S3-совместимо → Postiz может использовать это как хранилище (`STORAGE_PROVIDER=s3`).
- Не зависит от дома: файл отдаётся всегда.

### 3. Supabase Storage (0 ₽, без карты)
- 1 ГБ хранения, 5 ГБ трафика в месяц; публичный бакет → прямые ссылки.
- Подходит для шортсов при схеме «залил перед публикацией — удалил после».

### 4. Cloudflare R2 (нужна карта, списаний в бесплатном лимите нет)
- 10 ГБ хранения и бесплатная отдача, публичный домен `pub-<hash>.r2.dev` — свой домен не нужен.
- Лучшие лимиты из облаков.

## Что делать, когда владелец выберет
1. **Свой сервер:** DuckDNS-аккаунт → cron-скрипт обновления адреса → nginx-раздача папки
   с медиа → Let's Encrypt → проброс порта в роутере → проверить снаружи `curl -I` по ссылке.
2. **B2/Supabase/R2:** создать бакет, ключи доступа → добавить в
   `/home/postiz/postiz/docker-compose.yml` (переменные `STORAGE_PROVIDER=s3`, endpoint, ключи)
   → перезапустить Postiz → проверить, что ссылка из `FRONTEND_URL` стала публичной
   → подключить интеграции Instagram/Threads.

## Проверка перед подключением IG/Threads
Обязательно проверить фактом, а не на веру:
```
curl -I "<ссылка на файл>"      # должен быть 200 и content-type: video/mp4, без HTML
curl -s "<ссылка>" | head -c 200 # не должно быть HTML-страницы
```
Google Drive эту проверку не проходит: отдаёт HTML-страницу просмотра, а для файлов
больше 100 МБ — страницу «подтвердите скачивание». Поэтому Drive не подходит.
