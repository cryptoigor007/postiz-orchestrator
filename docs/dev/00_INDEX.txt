НАЗНАЧЕНИЕ ЭТОЙ ПАПКИ
--------------------------------------------------------------------------------
Пакет документов описывает:
  * как устроена система СЕЙЧАС (архитектура, потоки, данные);
  * СТАНДАРТ модульной организации — контракт, по которому пишутся
    платформенные модули (YouTube, Instagram, TikTok, Facebook, Threads...);
  * СТАНДАРТЫ API — единые правила интеграций (OAuth, ретраи, лимиты,
    идемпотентность, ошибки, секреты, тестирование);
  * ТЗ (техническое задание) на каждый модуль — отдельным файлом.

СТРУКТУРА
--------------------------------------------------------------------------------
docs/dev/00_INDEX.txt              — этот файл (навигация, статусы)
docs/dev/01_ARCHITECTURE.txt       — как устроена система сейчас (as-is)
docs/dev/02_MODULE_STANDARD.txt    — стандарт модульной системы + план миграции
docs/dev/03_API_STANDARDS.txt      — общие стандарты API/интеграций

docs/modules/MODULE_YOUTUBE.txt    — ТЗ модуля YouTube (ЭТАЛОН структуры ТЗ)
docs/modules/MODULE_INSTAGRAM.txt  — ТЗ модуля Instagram
docs/modules/MODULE_TIKTOK.txt     — ТЗ модуля TikTok
docs/modules/MODULE_FACEBOOK.txt   — ТЗ модуля Facebook
docs/modules/MODULE_THREADS.txt    — ТЗ модуля Threads

ПОРЯДОК ЧТЕНИЯ
--------------------------------------------------------------------------------
1) 01_ARCHITECTURE  — понять, что есть сейчас.
2) 02_MODULE_STANDARD — понять целевую модульную организацию и контракт модуля.
3) 03_API_STANDARDS  — понять правила, обязательные для ВСЕХ модулей.
4) MODULE_<PLATFORM> — ТЗ конкретного модуля (пишется по эталону YouTube).

СТАТУСЫ ДОКУМЕНТОВ
--------------------------------------------------------------------------------
[ГОТОВО]     00_INDEX, 01_ARCHITECTURE, 02_MODULE_STANDARD, 03_API_STANDARDS
[ГОТОВО]     MODULE_YOUTUBE (эталон)
[ГОТОВО]     MODULE_INSTAGRAM, MODULE_TIKTOK, MODULE_THREADS, MODULE_FACEBOOK
[В РАБОТЕ]   — (все ТЗ готовы, далее реализация по плану миграции Э1–Э6)

ТЕРМИНЫ (кратко)
--------------------------------------------------------------------------------
Ядро        — код оркестратора, не зависящий от платформы (расписание, БД,
              панель, Telegram-бот, бэкапы, наблюдаемость).
Модуль      — пакет кода под ОДНУ платформу (orchestrator/platforms/<id>/),
              реализующий контракт PlatformModule.
Реестр      — выбор и загрузка модуля по конфигу (engines.<platform>).
Брокер      — сервис выдачи/обновления OAuth-токенов платформ.
publishAt   — «отложенная публикация» на стороне платформы: загрузка заранее,
              публикация в назначенное время без нашего участия.
Клейм       — претензия Content ID / copyright на видео (проверка до публикации).

ПРАВИЛА ВЕДЕНИЯ ЭТИХ ДОКУМЕНТОВ
--------------------------------------------------------------------------------
* Формат TXT, структура разделов одинаковая для всех файлов.
* Любое расхождение кода и документа фиксируется в разделе «Открытые вопросы».
* Версии API и лимиты помечаются «проверить актуальность» и обновляются
  ежеквартально (см. 03_API_STANDARDS, раздел «Версионирование API»).
* Документы живут в репозитории (docs/), проходят ревью вместе с кодом.
