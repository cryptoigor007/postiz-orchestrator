[A1] Чекпойнт клеймов — канал (02§11.1)
  → Telegram-бот с кнопками; панель — дублирующий канал в v2.
  Почему: бот уже умеет диалоги и TTL-вопросы (missing_url), решается с телефона.
  Тест: тестовое сообщение с кнопками «✅ клеймов нет / ⚠️ есть клейм» →
        ответ владельца → система продолжает/пропускает публикацию; лог в publish_log.

[A2] Окно ранней загрузки по умолчанию (02§11.2, YT§16.1)
  → 24 часа (early_upload_hours=24, настраиваемо). Instagram — ограничено TTL
    контейнера (предохранитель 20 ч, включается отдельно — см. A-тест).
  Почему: сутки — гарантированное окно на обработку и клейм-чек; квота YouTube
          позволяет (1600 units — 1 загрузка, лимит ~6/сутки).
  Тест: тестовая загрузка с early_upload_hours=1 → видео приватно, publishAt
        выставлен, публикация происходит в назначенную минуту без участия системы.

[A3] Судьба «пропущенных» видео (02§11.3, YT§16.2)
  → Оставлять приватными, claims_state=claimed, напоминание боту раз в 7 дней;
    удаление — только командой вручную.
  Почему: удаление необратимо; место/квота есть; пригодится разобраться в причине.
  Тест: пометить тестовое видео claimed → не публикуется; напоминание приходит;
        команда удаления работает и чистит запись.

[A4] n8n/browser-движки (02§11.4)
  → Остаются адаптерами (не оформляются как модули этого стандарта).
  Почему: экспериментальные, своего контракта не дают; вытесняются модулями по мере готовности.
  Тест: конфиг с engines.x=n8n не падает при наличии реестра модулей.

[A5] Общий HTTP-клиент ядра (03§10.1)
  → ДА: orchestrator/http_client.py — таймауты, ретраи+backoff+jitter, Retry-After,
    маскирование секретов, учёт лимитов/RateLimit-хедеров; обязателен для модулей.
  Почему: единая политика ретраев/безопасности; уже есть injectable-http паттерн в движках.
  Тест: unit — 5xx→повтор с backoff; 429→ждём Retry-After; токен в логе замаскирован.

[A6] Единый формат ошибок для бота/панели (03§10.2)
  → Словарь orchestrator/errors.py: код → {«что случилось», «что делать»} (ru).
  Почему: одинаковые тексты в боте, панели и логах; проще локализовать и тестировать.
  Тест: для каждого кода таксономии непустые шаблоны (снапшот-тест).

[A7] Debug-логи HTTP (03§10.3)
  → По умолчанию ВЫКЛ; при включении — logs/http-debug, ≤10 МБ/запись, ретенция
    7 дней, маскирование; автоочистка.
  Почему: тела запросов содержат чувствительное; объём должен быть ограничен.
  Тест: включить → запрос → токен замаскирован; через 7 дней (эмуляция) файл удалён.

[A8] Плейлисты YouTube (YT§16.3) → v2 (после MVP). Тест: создание плейлиста при загрузке (post-MVP).
[A9] Таймкоды из плана VideoMaker (YT§16.4) → v2; в MVP описание идёт как есть
     (в long-описаниях таймкоды уже присутствуют). Тест: сверка описания публикации с исходником.

[A10] Instagram: где хранить container_id (IG§16.1)
  → Новое поле external_sub_id в entity_platform_status (аддитивная миграция).
    external_id = media_id после публикации, external_sub_id = container_id.
  Почему: единое место для «второго» идентификатора у всех платформ (TikTok post_id и т.п.).
  Тест: создать контейнер → рестарт сервиса → повторный цикл НЕ создаёт второй контейнер.

[A11] Instagram: источник лимита публикаций (IG§16.3)
  → Источник истины — endpoint content_publishing_limit; предохранитель ядра daily_limit=4.
  Почему: в доках Meta расхождение 100/50; endpoint отдаёт фактический остаток.
  Тест: на тестовом аккаунте вызвать endpoint — сверить остаток с нашим счётчиком.

[A12] Instagram: ранняя загрузка (IG§16.4, §16.9)
  → v1: at_slot (без ранней). Включение — v1.1 после практической проверки
    copyright_check_status и таймингов контейнера на тестовом аккаунте.
  Почему: контейнеры живут 24 ч, а выгоды в v1 меньше риска; Meta быстро обрабатывает.
  Тест: тестовый контейнер → проверить copyright_check_status и время FINISHED;
        затем решение о включении окна (по умолчанию 12 ч).

[A13] Instagram: delete (IG§16.5) → не включаем в v1 (scope instagram_manage_contents — v1.1).
[A14] Instagram: клеймы (IG§16.6) → manual в v1; auto (copyright_check_status) — v2 после проверки.
[A15] Instagram: фото/карусели (IG§16.7) → v2 (контент — видео).
[A16] Instagram: Stories (IG§16.8) → не планируем (v3+, только business, живут 24 ч).

[A17] TikTok: redirect URI (TT§16.2)
  → Одноразовая авторизация через актуальный cloudflared-URL; токены — в брокере
    (refresh 365 дней). Постоянный публичный домен для callback не требуется.
  Почему: туннель динамический; переавторизация редка; меньше инфраструктуры.
  Тест: провести привязку аккаунта на тестовом профиле, токены сохранены, refresh сработал.

[A18] TikTok: UX-чекпойнт перед Direct Post (TT§16.3)
  → Заложить бот-подтверждение (privacy+согласие) — актуально ТОЛЬКО при аудите (v2).
  Тест: смоделировать вопрос в боте; ответ учитывается в публикации.

[A19] TikTok: FILE_UPLOAD vs PULL_FROM_URL (TT§16.4)
  → FILE_UPLOAD (не требует верификации домена; работает для inbox).
  Почему: меньше внешних зависимостей; PULL_FROM_URL оставим как опцию при аудите.
  Тест: inbox-загрузка файла с тестового аккаунта — черновик появился.

[A20] TikTok: что считать «опубликовано» в inbox (TT§16.5)
  → Статус «draft_sent» (черновик доставлен) ≠ published. release_url нет;
    Telegram-ссылка не ждёт TikTok (она привязана к YouTube).
  Почему: честная модель: публикацию завершает владелец в приложении.
  Тест: inbox-тест → строка получает draft_sent, публикация не помечается выполненной.

[A21] TikTok: daily_limit (TT§16.6) → 5 (наш предохранитель).
[A22] TikTok: подпись/хэштеги (TT§16.7) → общий шаблон ядра; лимит 2200 UTF-16; упоминания не используем.
[A23] TikTok: webhooks vs polling (TT§16.8) → polling status/fetch (без вебхуков).
  Почему: нет стабильного публичного HTTPS; проще и достаточно.
[A24] TikTok: is_aigc (TT§16.9) → false по умолчанию, включается конфигом (для явно AI-контента).
[A25] TikTok: post_id (TT§16.10) → external_id=publish_id, external_sub_id=post_id (см. A10).

[A26] Facebook: routing контента (FB§16.1) → шортсы → Reels; длинные → обычное видео.

  загрузке; перенос = удалить и пересоздать (проверить практикой; если найдут API —

  Тест: практический тест переноса на тестовой странице; фиксируем результат в ТЗ.
[A28] Facebook: DRAFT-механика (FB§16.3) → не используем; только SCHEDULED.
[A29] Facebook: обложка в MVP (FB§16.4) → нет (v1.1: доп. scopes).
[A30] Facebook: scope publish_video (FB§16.5) → запросить при подключении; проверить фактом

--------------------------------------------------------------------------------
  B. ТЕСТ ДЛЯ ВЛАДЕЛЬЦА (5 вопросов)
--------------------------------------------------------------------------------
Правила: для каждого вопроса — варианты, «мой выбор» (рекомендация) и «вероятный
твой выбор» (оценка по твоим приоритетам: минимальный ручной труд, максимальная
надёжность, 0 расходов).

== Q1. TikTok: как публикуем? (TT§16.1) ==
  1) Inbox-черновики: видео падает в «черновики», ты публикуешь в приложении (1 мин).
     Плюс: без аудита, без риска блокировки. Минус: ручной шаг.
  2) Подавать на аудит Direct Post. Плюс: полный автомат. Минус: правила TikTok
     прямо называют «утилиты для своих аккаунтов» неприемлемыми → отказ вероятен;
     плюс требования аудита (ручной выбор приватности, согласие).
  3) Через Postiz (если его приложение прошло аудит).
  МОЙ ВЫБОР: 1. ВЕРОЯТНЫЙ ТВОЙ: 1 (минимум риска и возни).

== Q2. Хостинг медиа для Instagram/Threads (IG§16.2, TH§16.1; см. STORAGE-OPTIONS.md) ==
  Нужен публичный HTTPS-URL, Meta скачивает файл один раз (паттерн «залил→опубликовал→удалил»).
  1) Backblaze B2: 10 ГБ бесплатно, S3-совместимо, адрес вида f000.backblazeb2.com.
  2) Cloudflare R2: 10 ГБ, отдача бесплатно; требуется карта (списаний нет).
  3) Supabase Storage: 1 ГБ, 5 ГБ трафика/мес (тесно для видео).
  4) Свой сервер (DuckDNS + nginx): 0 ₽, но зависит от дома/электричества и проброса портов.
  МОЙ ВЫБОР: 1. ВЕРОЯТНЫЙ ТВОЙ: 1 (0 ₽, без карты, не зависит от дома).

== Q3. Судьба пропущенных (клейм) видео (02§11.3, YT§16.2) ==
  1) Оставлять приватными + напоминание раз в 7 дней; удалять вручную. (хранение не жалко)
  2) Автоудаление через 7 дней.
  3) Спрашивать каждый раз у тебя.
  МОЙ ВЫБОР: 1. ВЕРОЯТНЫЙ ТВОЙ: 1 (ничего не теряется, напомним).

== Q4. Окно ранней загрузки YouTube (YT§16.1) ==
  1) 24 часа — максимум времени на обработку и проверку клеймов.
  2) 12 часов — меньше лежит «в столе».
  3) Отложить раннюю загрузку (пока at_slot).
  МОЙ ВЫБОР: 1. ВЕРОЯТНЫЙ ТВОЙ: 1 (надёжность важнее).

== Q5. Тестовые аккаунты для новых платформ (IG/TikTok/FB/Threads) (IG§16.10, TH§16.6) ==

  2) Использовать основные аккаунты (быстро, но тесты видны подписчикам).
  3) Позже.
  МОЙ ВЫБОР: 1. ВЕРОЯТНЫЙ ТВОЙ: 1 (боевые каналы не трогаем).
