  ТЗ МОДУЛЯ: TELEGRAM  (orchestrator/platforms/telegram)
  Версия ТЗ: 1.0   |   Дата: 24.09.2026   |   Этап миграции: Э3
================================================================================
Модуль публикует посты в Telegram-канал/чат от имени бота: ссылочные посты
(основной сценарий — текст + ссылка на YouTube с превью и кнопкой), медиа-посты,
правку и удаление. Заменяет текущие ветвления ядра «send_via=bot».

--------------------------------------------------------------------------------
1. ОБЛАСТЬ РАБОТ (SCOPE)
--------------------------------------------------------------------------------
Входит:
  * отправка: sendMessage / sendVideo / sendPhoto (по режиму поста);
  * ссылочный режим (post_mode=link): текст + превью над текстом + кнопка «Смотреть»;
  * правка: editMessageText (когда ссылка YouTube появилась позже);
  * удаление: deleteMessage (для сценариев «удалить и пересоздать»);
  * статусы: message_id, t.me-ссылка (для публичных каналов), ошибки.
Не входит:
  * приём обновлений (опрос команд бота живёт в ядре — telegram_bot/transport);
  * медиа-хостинг, webhook-сервер, локальный Bot API (не нужны в v1).

--------------------------------------------------------------------------------
2. API
--------------------------------------------------------------------------------
Telegram Bot API: https://api.telegram.org/bot<token>/<method>
Используемые методы:
  sendMessage         — текстовые/ссылочные посты (parse_mode=HTML, link_preview_options)
  sendVideo           — видео (≤ 50 МБ через Bot API!)
  sendPhoto           — фото (≤ 10 МБ)
  editMessageText     — правка текста (и reply_markup)
  editMessageMedia    — замена медиа (v1.1; требует поддержки в Bot API)
  deleteMessage       — удаление сообщения
  getMe               — проверка токена;  getChat — проверка прав/канала
Версия API: Bot API 9.x (проверить актуальность; методы стабильны годами).
Транспорт: HTTPS Bot API (никаких вебхуков в v1 — не требуется).

--------------------------------------------------------------------------------
3. АВТОРИЗАЦИЯ
--------------------------------------------------------------------------------
Схема: bot_token (из .env; бессрочный, отзывается только вручную в @BotFather).
Требования:
  * бот — администратор канала (права: публикация сообщений; для правок — редактирование);
  * whitelist чатов уже реализован в ядре (allowed_chat_ids).
auth_status(): getMe + проверка getChat(publish_chat_id) и прав бота (sender_chat/admin).
Ошибки: 401/«Unauthorized» → AUTH_REQUIRED (токен неверный/отозван).

--------------------------------------------------------------------------------
4. КВОТЫ И ЛИМИТЫ
--------------------------------------------------------------------------------
* Общий лимит: ~30 сообщений/сек суммарно по боту (официально «30 msg/sec», проверить);
* В один чат: ~20 сообщений/минуту (проверить);
* Файлы через Bot API: видео ≤ 50 МБ, фото ≤ 10 МБ (жёсткие лимиты Bot API!);
* Bot API upload большего размера невозможен без локального Bot API server (вне v1);
* Наш предохранитель daily_limit — в ядре (safety).

--------------------------------------------------------------------------------
5. МЕДИА-ТРЕБОВАНИЯ
--------------------------------------------------------------------------------
Видео: mp4 (H.264/AAC), 9:16 предпочтительно, ≤ 50 МБ (иначе — ошибка с понятным
  текстом; крупные файлы публикуются как ссылка, а не файл).
Фото: JPG/PNG ≤ 10 МБ.
Текст: caption ≤ 1024 символа (для медиа), message ≤ 4096 символов; parse_mode=HTML;
  ссылки и эмодзи — как есть; HTML-теги экранировать.

--------------------------------------------------------------------------------
6. РЕЖИМЫ РАБОТЫ МОДУЛЯ
--------------------------------------------------------------------------------
6.1 at_slot (единственный; publish=true)
    Публикуем в момент слота: у Telegram нет аналога publishAt.
    capabilities: early_upload=false, schedule_publish=false.
6.2 link (основной для проекта)
    Пост = title + description + «▶ Смотреть на YouTube: <link>», превью над текстом
    (link_preview_options.show_above_text), кнопка url на видео.
    Если ссылка появилась ПОСЛЕ публикации — editMessageText (это уже делает ядро;
    модуль предоставляет update_metadata()).
6.3 disable_notification / silent (опция конфига) — для ночных постов.

--------------------------------------------------------------------------------
7. ПРОЦЕСС ПУБЛИКАЦИИ
--------------------------------------------------------------------------------
1) Ядро выбирает контент и время (Telegram = YouTube-слот + telegram_link_delay_min).
2) Модуль: send_* → message_id.
3) release_url: для публичного канала t.me/<username>/<message_id>
   (username из getChat); иначе храним chat_id+message_id и t.me-ссылку не даём.
4) Ядро: статус published; поздняя правка при появлении ссылки YouTube (editMessageText).
5) Уведомления владельцу и бот-меню — вне модуля (ядро).

--------------------------------------------------------------------------------
8. ОСОБЕННОСТИ ПЛАТФОРМЫ
--------------------------------------------------------------------------------
* Лимит 50 МБ на видео через Bot API — планируем ссылочные посты (наш случай) и
  короткие файлы; больше — не отправляем, а сообщаем причину.
* deleteMessage: сообщения старше 48 ч бот может не удалить (проверить на канале).
* Правка чужих/пересланных сообщений невозможна.
* Канал должен быть публичным для t.me-ссылки; для приватных — только message_id.
* Альбомы (media groups) — не используем в v1.

--------------------------------------------------------------------------------
9. КЛЕЙМЫ
--------------------------------------------------------------------------------
Не применимо: claims_check = unsupported (ручной чекпойнт не нужен).

--------------------------------------------------------------------------------
10. ОШИБКИ И ИХ ОБРАБОТКА
--------------------------------------------------------------------------------
400 chat not found / chat_id is empty        → PLATFORM_REJECTED (проверить publish_chat_id)
400 message is too long / caption too long   → MEDIA_INVALID (обрезать по шаблону ядра)
400 file too big / Request Entity Too Large  → MEDIA_INVALID (лимит 50 МБ)
403 forbidden: bot was blocked / kicked /
    not enough rights                        → AUTH_REQUIRED / PLATFORM_REJECTED
401 Unauthorized                             → AUTH_REQUIRED
429 Too Many Requests (retry_after)          → RATE_LIMIT (backoff строго по retry_after)
5xx / время ожидания                         → TRANSIENT (ретраи)
Прочее                                       → FATAL
Тексты — по-русски, с действием («проверьте права бота в канале» и т.п.).

--------------------------------------------------------------------------------
11. КОНФИГ (пример секции config.yaml)
--------------------------------------------------------------------------------
platforms:
  telegram:
    enabled: true
    project: tochka
    post_mode: link            # link | media
    send_via: bot              # bot | postiz (совместимость)
    publish_chat_id: "-1003882726633"   # канал «Точка наблюдения»
    link_preview_above: true
    video_variant: vertical
    daily_limit: 5
    module:                    # НОВЫЕ поля модуля
      parse_mode: HTML
      disable_notification: false
      max_video_mb: 50         # предохранитель под лимит Bot API
engines:
  telegram: "module:telegram"  # или "postiz" (совместимость)

--------------------------------------------------------------------------------
13. ТЕСТЫ
--------------------------------------------------------------------------------
Unit (моки HTTP): send/edit/delete — корректные тела запросов; маппинг ошибок
  (400/403/429 retry_after/5xx); обрезка длинных текстов; лимит 50 МБ (явная ошибка).
Contract (тестовый канал/чат): полный цикл send → edit → delete; проверка t.me-ссылки.
Dry-run: без реальных отправок.

--------------------------------------------------------------------------------
14. КРИТЕРИИ ПРИЁМКИ
--------------------------------------------------------------------------------
[ ] Отправка ссылочного поста с превью над текстом и кнопкой
[ ] Правка текста после появления ссылки YouTube
[ ] Удаление и пересоздание (delete+send) работают
[ ] Лимит 50 МБ даёт понятную ошибку, а не «падение»
[ ] 429 обрабатывается по retry_after; 403 → понятный текст и алерт

[ ] Тесты зелёные; прод-поведение не изменилось (сравнение до/после Э3)
[ ] Ядро больше не содержит ветвлений send_via (перенесены в модуль)
