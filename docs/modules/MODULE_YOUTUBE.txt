  ТЗ МОДУЛЯ: YOUTUBE  (orchestrator/platforms/youtube)
  Версия ТЗ: 1.0   |   Дата: 24.09.2026   |   Статус: эталон для остальных ТЗ
================================================================================
Модуль публикует видео на YouTube-канал: загрузка заранее (скрыто) с отложенной
публикацией (publishAt), немедленная публикация, правка метаданных, удаление,
проверка статусов. Источник контента — папки VideoMaker/ShortsMaker.

--------------------------------------------------------------------------------
1. ОБЛАСТЬ РАБОТ (SCOPE)
--------------------------------------------------------------------------------
Входит:
  * OAuth-авторизация канала (через токен-брокер), авто-refresh;
  * загрузка видео (resumable upload) с метаданными;
  * ранняя загрузка: privacy=private + publishAt (по умолчанию за 24 ч до слота);
  * управление публикацией: смена publishAt, снятие публикации, удаление;
  * установка обложки (thumbnail);
  * статусы: обработка/публикация/ошибки, URL видео;
  * маппинг ошибок (включая «аккаунт не верифицирован», квоты, авторизацию).
Не входит (в других модулях/ядре):
  * Telegram (отдельный модуль), планирование слотов (ядро), клейм-диалог (ядро).

--------------------------------------------------------------------------------
2. API
--------------------------------------------------------------------------------
Платформа: YouTube Data API v3 (googleapis.com/youtube/v3)
  Загрузка:        POST https://www.googleapis.com/upload/youtube/v3/videos
                   ?uploadType=resumable&part=snippet,status
  Метаданные:      PUT  https://www.googleapis.com/youtube/v3/videos?part=snippet,status
  Список/статусы:  GET  https://www.googleapis.com/youtube/v3/videos?part=snippet,status,processingDetails,contentDetails
  Обложка:         POST https://www.googleapis.com/upload/youtube/v3/thumbnails/set?videoId=...
  Удаление:        DELETE https://www.googleapis.com/youtube/v3/videos?id=...
  Плейлисты:       GET/POST https://www.googleapis.com/youtube/v3/playlistItems (опционально, v2)
  Канал:           GET  https://www.googleapis.com/youtube/v3/channels?part=contentDetails&mine=true
Content ID (клеймы): публичный API НЕ отдаёт. Только YouTube CMS/Partner API
  (Content ID API) — доступен партнёрам. Для обычного канала = unsupported.
Версия API: v3 (проверить актуальность раз в квартал).

--------------------------------------------------------------------------------
3. АВТОРИЗАЦИЯ
--------------------------------------------------------------------------------
Схема: OAuth 2.0 Authorization Code (Google), offline access (refresh_token).
Scopes (минимум):
  https://www.googleapis.com/auth/youtube.upload      — загрузка
  https://www.googleapis.com/auth/youtube             — управление видео
  https://www.googleapis.com/auth/youtube.force-ssl   — удаление/правка (уже используется)
Токены: хранит токен-брокер (tokens/youtube.json, 600). Access-token живёт ~1 час,
  обновляется автоматически через refresh_token.
Клиентские ключи: client_id/client_secret — в .env (получены из Google Cloud
  OAuth-приложения). Проект OAuth должен быть «In production» (иное — refresh
  токены живут 7 дней; см. примечание в §9).
Аккаунт-требование: канал должен быть ВЕРИФИЦИРОВАН (иначе обложки не ставятся —
  ошибка «account is not verified»). См. §9 и §10.

--------------------------------------------------------------------------------
4. КВОТЫ И ЛИМИТЫ (проверить актуальность)
--------------------------------------------------------------------------------
Базовая квота проекта: 10 000 units/сутки (общая с Postiz, если он использует
тот же GCP-проект!).
Стоимость операций:
  videos.insert          — 1600 units
  thumbnails.set         — 50
  videos.update          — 50
  videos.delete          — 50
  videos.list / channels — 1
Практический предел: ~5–6 загрузок/сутки. При росте — заявка на увеличение
квоты в Google Cloud (бесплатно, но с обоснованием).
Предохранитель ядра: platform.youtube.daily_limit (safety).

--------------------------------------------------------------------------------
5. МЕДИА-ТРЕБОВАНИЯ
--------------------------------------------------------------------------------
Видео (загрузка):
  контейнер: mp4 (MOV допускается), H.264 + AAC (рекомендуемые)
  Shorts: 9:16, ≤ 3 минут (актуально для Shorts), ≥ 1080×1920
  Long:   16:9, широкий формат, до 12 часов (верифицированный канал)
  размер: до 256 ГБ / 12 часов (лимит YouTube; у нас файлы на порядки меньше)
Обложка (thumbnail):
  JPG/PNG, ≤ 2 МБ, рекомендуется 1280×720 (16:9) или 1080×1920 (Shorts)
  (недоступно, пока канал не верифицирован)
Метаданные:
  title ≤ 100 символов; description ≤ 5000; tags ≤ 500 символов суммарно;
  madeForKids: false (взрослый контент); categoryId по умолчанию (22 = People & Blogs,
  уточнить в конфиге).

--------------------------------------------------------------------------------
6. РЕЖИМЫ РАБОТЫ МОДУЛЯ
--------------------------------------------------------------------------------
6.1 early_upload (ОСНОВНОЙ, целевой)
    upload(media, meta, when=future):
      privacyStatus=private, publishAt=when (RFC3339, UTC)
      → videoId + URL известны СРАЗУ; видео скрыто от зрителей
    До наступления when допускается:
      * schedule_publish(new_when) — перенести;
      * снять публикацию (privacyStatus=private без publishAt);
      * update_metadata(title/description/tags/thumbnail);
      * delete() — удалить.
    В момент when YouTube публикует видео сам.
    Плюсы: ссылка заранее (Telegram не ждёт), окно на проверку клеймов.
6.2 at_slot (совместимость)
    publish(media, meta) в момент слота — как делает Postiz сейчас.
6.3 test_publish
    Публикация тестового поста на тестовый канал (test_integration_ids).

--------------------------------------------------------------------------------
7. ПРОЦЕСС ПУБЛИКАЦИИ (early_upload; шаги и данные)
--------------------------------------------------------------------------------
Шаг 1. Ядро создаёт строку entity_platform_status (platform=youtube,
       publish_mode=early_upload, scheduled_at=slot).
Шаг 2. Модуль: prepare(media) → проверки; upload(..., when=slot):
       resumable upload → videoId; сразу update_metadata + thumbnails.set.
Шаг 3. Запись в БД: external_id=videoId, release_url=https://youtu.be/<id>,
       scheduled_at=slot, status='scheduled', publish_mode='early_upload'.
Шаг 4. (ядро) чекпойнт клеймов за K часов (§8).
Шаг 5. get_status(): до publishAt — processing/scheduled; после — published.
Шаг 6. (ядро) Telegram-пост со ссылкой (ссылка уже есть — ожидания нет).
Ошибки на любом шаге → маппинг в §9, запись last_error, алерт при необходимости.

--------------------------------------------------------------------------------
8. КЛЕЙМЫ
--------------------------------------------------------------------------------
API: unsupported (Content ID только у партнёров).
Стратегия:
  * ручной чекпойнт ядра: за K часов (по умолчанию 2 ч) до публикации бот
    спрашивает владельца кнопками: [✅ Клеймов нет — публикуем]
    [⚠️ Есть клейм — пропустить];
  * при «есть клейм»: снять publishAt/оставить приватным → claims_state=claimed
    → взять следующий кандидат на слот (backlog);
  * «клеймов нет» → ничего не делаем, публикация произойдёт по расписанию.
Возможное развитие (вне этого ТЗ): парсинг почтовых уведомлений YouTube,
автоматизация Studio (рискованно, нужен отдельный разбор).

--------------------------------------------------------------------------------
9. ОШИБКИ И ИХ ОБРАБОТКА
--------------------------------------------------------------------------------
Код/сообщение                              → Таксономия        → Действие
401 invalid_credentials / expired token    → AUTH_EXPIRED      → refresh + retry
403 accountNotVerified (обложка)           → PLATFORM_REJECTED → предупреждение,
                                              видео публикуется без обложки;
                                              АЛЕРТ: «верифицируйте канал»
403 quotaExceeded                          → QUOTA             → пауза до сброса
403 forbidden / uploadLimitExceeded        → RATE_LIMIT        → backoff, пауза
400 invalid request (метаданные/файл)      → MEDIA_INVALID     → ошибка + причина
404 videoNotFound                          → FATAL             → ошибка строки
5xx / timeout                              → TRANSIENT         → ретраи (backoff)
uploadStatus=failed/rejected               → PLATFORM_REJECTED → ошибка, при
                                              rejectionReason показать текст
Текст для владельца — по-русски, с указанием причины и действия.
ВАЖНО (кейс 24.09.2026): при ошибке на шаге обложки YouTube уже загрузил видео,
  но API-ответ приходит как ошибка. Модуль ОБЯЗАН: при наличии videoId
  фиксировать результат как «загружено, обложка не встала», не терять videoId
  и ссылку, и не переводить пост в «ERROR без URL» (как Postiz).

--------------------------------------------------------------------------------
10. ПРИМЕЧАНИЯ ПО OAuth-ПРИЛОЖЕНИЮ
--------------------------------------------------------------------------------
* Статус OAuth-приложения (Google Cloud): «Testing» → refresh_token истекает
  через 7 дней (нужна переавторизация раз в неделю). «In production» (без
  платной верификации, до 100 пользователей) → токены долгоживущие.
  РЕКОМЕНДАЦИЯ: переключить в In production; проверить экран согласия.
* Приложение должно разрешать scopes из §3; при их изменении — переавторизация.
* Секреты и токены — только в .env/брокере (см. 03_API_STANDARDS §6).

12. ТЕСТЫ
--------------------------------------------------------------------------------
Unit (моки HTTP):
  * upload: корректный resumable-старт, publishAt в теле status, парсинг videoId;
  * thumbnails.set: ошибка «not verified» → предупреждение, videoId сохраняется;
  * маппинг ошибок 401/403/429/400/5xx/uploadStatus;
  * schedule_publish/снятие публикации; delete; get_status.
Contract (тестовый канал):
  * полный цикл: upload(private+publishAt через 10 мин) → get_status → published;
  * обложка (после верификации канала);
  * отмена: снять publishAt → видео остаётся private.
Dry-run: без реальных загрузок.

14. ПЛАН ВНЕДРЕНИЯ
--------------------------------------------------------------------------------
1) API-клиент + OAuth через брокер (свой storage + refresh)
2) upload + publishAt + get_status; тесты
3) Интеграция в ядро (publisher/scheduler через контракт модуля)
4) Ранняя загрузка на тестовом канале (24 ч, приватно, publishAt=+10 мин)
5) Ручной чекпойнт клеймов (бот-кнопки) + skip→next
6) Боевое включение YouTube (engines.youtube=module:youtube), мониторинг 3 дня
7) Переключение OAuth-приложения в In production; верификация канала
   (отдельные действия владельца — см. §9, §10)
